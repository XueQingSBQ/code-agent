## 💎 核心亮点（必背）

### 1. 三个关键 Bug 修复

| Bug | 现象 | 根因 | 修复 |
|-----|------|------|------|
| **A - 截断梯阶永不放弃** | 输出截断后无限重试 | `next_turn()` 无条件重置计数器 | 添加 `reset_recovery` 参数 |
| **B - 重试变成 prefill** | 模型续写半句话而非重新回答 | 保留了截断的 assistant 消息 | 回滚到 `request_messages` |
| **C - 重试重放流** | 文本重复渲染 | 没有防护已消费的流 | `produced` 标志保护 |

### 2. 查询循环五步（背下来）

```
1. 准备上下文  → 修复孤儿 tool_use + 压缩历史
2. 流式 + 分发  → 边流式边 create_task(工具)
3. 收集结果    → gather_remaining()
4. 特殊停止原因 → 窗口耗尽/截断 → 压缩或恢复
5. 继续或停止  → 有 tool_use → 循环，否则 Done
```

**关键**：不是 ReAct，只看有没有 `tool_use` 块。

### 3. 截断恢复梯阶

```
1st 截断 → escalate (8k→16k, 丢弃半成品, 重试)
2nd 截断 → nudge    (保留 + "继续"提示)
3rd 截断 → nudge    (再次保留 + 提示)
4th 截断 → give up  (返回 UNRECOVERED)
```

### 4. 并发安全设计

```python
class WriteTool(Tool):
    concurrency_safe: ClassVar[bool] = False  # 必须声明
```

- `True` → 并发运行
- `False` / 缺失 / 未知 → **串行屏障**（等待所有已分发的任务）
- 四道防御：`__init_subclass__` + registry + mypy + 测试

**为什么不用 TaskGroup？** → 它会在一个任务失败时取消兄弟任务，但每个 `tool_use` 必须产生 `tool_result`。

## ❓ 高频问题速答

### Q: 为什么不用 LangChain？
**A**: LangChain 是 RAG 框架，解决"怎么调模型"。我要解决的是"怎么让它可靠运行"——失败恢复、精确并发控制、上下文管理，这些 LangChain 都不提供。

### Q: 为什么选 Python 不选 Rust？
**A**: 
- ✅ 生态成熟（SDK/测试框架直接可用）
- ✅ 10-14 周业余时间，快速迭代
- ⚠️ 性能不是瓶颈（API 延迟是秒级，语言是毫秒级）
- 用 mypy strict mode 补偿类型安全

### Q: Grep 为什么有两个后端？
**A**: 
- ripgrep 快但不是所有环境都装
- 一个回答"先装 ripgrep"的工具是死路（模型无法装软件）
- 纯 Python 后备保证可用性
- **测试强制两个后端输出字节相同**（输出格式是工具契约）

### Q: 如何保证架构不腐化？
**A**: `import-linter` + CI 强制检查，契约包括：
- 严格分层（cli → sdk → engine → providers → tools）
- 禁止反向依赖（tools 不能 import engine）
- 违反契约 → CI 失败

### Q: 测试覆盖率为什么不是 100%？
**A**: 
- 85% 已覆盖所有关键路径（循环/工具/恢复 >90%）
- 剩余 15% 是罕见错误分支和 CLI 入口
- 性价比递减：85%→95% 需要大量 mock
- 用真实文件系统测试更能发现问题

## 🎨 架构图（能画出来）

```
┌─────────────────────────────────┐
│  CLI (Rich 终端渲染)             │
├─────────────────────────────────┤
│  SDK (可编程接口)                │
├─────────────────────────────────┤
│  Engine (循环+执行器+状态)        │
├─────────────────────────────────┤
│  Provider (Anthropic API 适配)   │
├─────────────────────────────────┤
│  Tools (fs + search + shell)     │
└─────────────────────────────────┘
```

**分层原则**：
- 下层不知道上层存在
- 事件向上流动，命令向下流动
- import-linter CI 强制
