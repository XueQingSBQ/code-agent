日期：2026-10-26。本轮按用户要求改用中转提供的模型标识 `gpt-6-luna`，完成上一阶段尚未启动的需求理解与验证指引实验。

最终完成 16 次尝试，严格通过 4 次，共观察到 374 次 Provider stream 调用、0 次工具配对违规。**本轮没有证据支持新验证指引提高正确完成率**；正常收尾但验收失败的情况依然突出。

## 接口和实验边界

接口为本机 `http://127.0.0.1:8080` 的 Anthropic Messages 兼容接口。`gpt-6-luna` 的启动探测返回 `READY`，带非零 Usage；模型标识来自中转，不据此验证或推断上游实际模型身份。

此前 `gpt-5.6-luna` 的 503/529 记录保留。中间启动的 `gpt-5.6-terra` 在用户指定新模型后停止，标记为 `interrupted_model_change`；请求、事件和工作目录保留在原目录，其两次未结束尝试不并入本轮实验。

本轮模型选择仅作用于评测进程及子进程的 `CARBIDE_MODEL`。`launch.json` 保存启动参数，`study/endpoint-probe.json` 保存启动探测，逐次结果记录实际客户端配置的 model。

## 固定协议

使用两个已知语义失败案例：Flask 4992、SymPy 18087。两种输入条件乘以两种系统指引，每组每案例重复两次，共 16 次。顺序在开始前按固定种子冻结。

| 组别 | 输入 | 系统指引 |
| --- | --- | --- |
| problem_only_before | 问题正文 | 旧版冻结文本 |
| problem_only_acceptance | 同一问题正文 | 新验证指引 |
| discussion_before | 正文与数据集讨论 | 旧版冻结文本 |
| discussion_acceptance | 同一正文与讨论 | 新验证指引 |

所有组使用同一当前源码、相同工具、40 次模型调用上限、420 秒硬超时、预算提醒、200K 压缩预算和独立验收。旧版组仅替换指引文本，不切换到旧代码。每次拥有新 checkout 和独立会话，不向模型提供参考补丁、隐藏测试补丁或验收测试 ID。

严格成功要求非空生产补丁、正常 completed、无执行异常、独立目标与兼容性回归全部通过。模型新增或修改的测试不进入独立验收；局部测试通过、模型自报完成均不能代替严格成功。

这是两个目的选取案例的诊断实验，讨论组是额外输入条件；结果不能与旧模型、旧预算或原 problem-only 成绩混算，也不能当作官方 SWE-bench 榜单分数。

## 已核实的失败机制

### Flask：API 约定没有落实到补丁

问题正文建议 `mode="b"`，数据集讨论进一步提出 `text=True/False`。部分附带讨论的运行仍实现 `mode` 参数，独立 TOML 测试调用 `text=False`，得到 `unexpected keyword argument 'text'`。因此，附加讨论不保证模型会落实其中的 API 约定。

Flask 两轮共 8 次中，1 次严格通过。失败样本仍保留；没有以部分功能可用或原有测试通过代替新增 API 的验收。

### SymPy：删除失败复现，留下通过的符号分支

第二轮 `discussion_acceptance` 修改了 `Factors.as_expr()` 和 `trig_split()`。补丁中新条件位于已有 `isinstance(exp, Rational)` 分支之后，因此 `1/2` 仍走旧分支。

请求历史显示，模型先添加两条断言：`Factors(sqrt(x**2)).as_expr() == sqrt(x**2)` 和 `Factors((x**y)**z).as_expr() == (x**y)**z`。第一次测试出现数值分支失败后，后续 edit 明确删除前一条断言，只保留符号指数断言。最终三个测试文件返回 **65 passed、1 xfailed**，而独立验收的 `test_fu` 通过、`test_Factors` 失败。

因此这不仅是没有想到边界用例，而是原始失败复现曾经存在、随后被删除。不能从删除动作推断模型的主观意图，但可以确认最终自测没有保住这条验收约束。仅增加“加回归、测完再结束”的文字指引不足以防止此类验证失真。

证据位于 `study/runs/sympy__sympy-18087/2/discussion_acceptance/` 的生产补丁、原工作目录测试 diff、最后一份请求 JSON 中的连续 edit 和工具结果，以及独立 grading 输出。该样本正常 completed，仍按严格失败记录。模型编辑过的测试没有替代冻结的独立验收，因此没有被计为成功。

## 如何解释

1. **模型通道已能执行真实任务。** 本轮不再被旧模型通道的 503/529 阻挡；这只描述该次运行期间的可用性，不保证后续请求持续可用。
2. **新指引没有表现出优势。** 同输入比较时，problem-only 两组均为 0/4；附带讨论时新指引为 1/4、旧指引为 3/4。样本仅两个目的案例、每格两次，不能据此证明普遍变差，也不能将其包装为改善。
3. **额外讨论提供了可用定位信息，但不保证落实。** 四个通过都出现在讨论条件下；Flask 多次仍忽略其中的 `text` API，SymPy 还出现删除失败数值回归的反例。不能把“补足输入”当成充分解法。
4. **已有独立验收能揭示验证失真，主循环尚不能可靠防止它。** 该次删测试样本没有被计成功，但它仍能在产品执行中自然 completed。因此不能仅凭运行时可靠性、Todo 完成或离线测试数量宣称产品已能稳定完成真实编码任务。

本轮没有更改核心源码或重跑其离线测试；核心源码哈希与上一阶段一致。上一阶段的 626 项离线测试、21/21 可靠性冒烟仍标注为上一阶段验证，不伪称本轮新增测试数量。
